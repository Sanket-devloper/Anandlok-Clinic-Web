# Hostinger Single-App Setup for Anandlok

This document describes the recommended production setup for the clinic website on Hostinger using **one Node.js app** to serve both the frontend and backend.

## Recommended Approach

Use a single Express server for production:

- Serve the built React/Vite frontend as static files
- Handle backend routes under `/api`
- Keep one domain, one deployment, one app process

This is the simplest durable setup for a small clinic website.

## Suggested Folder Structure

A practical structure for the single-app setup looks like this:

```text
anandlok-web/
├─ src/
│  ├─ components/
│  ├─ pages/
│  ├─ layouts/
│  ├─ hooks/
│  ├─ lib/
│  ├─ assets/
│  ├─ App.tsx
│  └─ main.tsx
├─ server/
│  ├─ app.js
│  ├─ server.js
│  ├─ routes/
│  │  ├─ health.route.js
│  │  └─ appointment.route.js
│  ├─ middleware/
│  │  ├─ errorHandler.js
│  │  ├─ notFound.js
│  │  └─ spamProtection.js
│  ├─ config/
│  │  ├─ env.js
│  │  └─ cors.js
│  └─ services/
│     └─ (future services)
├─ dist/                 # generated frontend build output
├─ package.json
├─ vite.config.ts
├─ .env
└─ .env.example
```

## What Each Part Does

- `src/`: the React frontend
- `server/`: the Node/Express backend
- `server/routes/`: API endpoints like health checks and future booking routes
- `server/services/`: reusable logic for future backend features
- `dist/`: production frontend build generated by Vite

## Production Flow

### 1. Frontend build

Run the Vite build to generate optimized static files:

```bash
npm run build
```

This creates the `dist/` folder.

### 2. Server starts

The Node app starts and does two jobs:

- serves `dist/` as static website files
- exposes API routes like `/api/health`

### 3. Browser requests

- `/` loads the homepage
- `/services` loads frontend routes through React Router
- the contact section shows social links, phone, and map details

### 4. React routing fallback

For direct browser visits to frontend routes, the server should return `index.html` so the React app can handle routing.

## Deployment Flow on Hostinger

### Step 1: Prepare the code

- Keep the frontend and backend in the same repository
- Make sure the server can run with `npm start`
- Make sure the frontend can build with `npm run build`

### Step 2: Set environment variables

Add production values in Hostinger, such as:

- `NODE_ENV=production`
- `PORT` provided by Hostinger
- allowed frontend origin if needed

### Step 3: Upload or deploy the app

Use Hostinger Managed Node.js app and point it to the project root.

### Step 4: Configure start command

The production start command should run the Node server.

Example:

```bash
npm start
```

### Step 5: Point the domain

Since the domain is on GoDaddy:

- update DNS to Hostinger nameservers or records
- point the domain to the Hostinger app

### Step 6: Test production

Verify these URLs after deployment:

- `/` for the homepage
- `/api/health` for backend health
- social-link section on the contact page
- appointment button redirect to Google Form

## Recommended App Responsibilities

### Frontend

- all pages and UI
- gallery, services, blog, contact page
- appointment button redirect

### Backend

- health checks
- future booking/API routes if needed later

### Appointment system

- keep Google Form for now
- it is cheaper and lower maintenance
- later you can replace it with a custom booking flow if needed

## Recommended Implementation Order

1. Merge backend into a single production app structure
2. Keep `/api/health` and any future routes minimal
3. Add Google Form appointment handling when ready
4. Deploy to Hostinger
5. Point GoDaddy DNS to Hostinger

## Notes

- For this website, one Node app is enough
- Keep Google Form for appointments until you truly need a custom booking system
- Use social links as the primary contact discovery method
- Add WhatsApp as a secondary quick-contact option only if needed

## Summary

The best long-term setup for Anandlok is:

- one Node app
- one domain
- one deployment
- frontend served by Express
- backend APIs served by the same Express app

This gives you a simple and maintainable system for a clinic website.
